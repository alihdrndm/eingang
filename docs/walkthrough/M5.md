# M5 — The LLM layer: one client, budgets, extraction, comparison, explanations

## What was built

- **One door to OpenAI** (`llm/client.py`). Every call is a `Request` with a prompt version, fenced untrusted data, a strict output schema and a token limit. The client checks the budgets, looks in the cache, calls the API, parses the structured answer and writes one ledger row (`LlmCall`) with tokens, cost and status, never the prompt or the answer. An import-linter contract keeps every other module away from the SDK.
- **Budgets** (`llm/budget.py`): $2.00 for the project's lifetime, $1.50 per month, $0.10 per day for public sandbox use and 3 calls per sandbox. Before a call, the worst case (every allowed output token) must fit; the ledger records the real cost. `LLM_ENABLED=false` refuses every call without touching the network.
- **Three features**, wired into the workflow's activities: extraction of a PDF-only invoice with per-field confidence and evidence (graded in `invoices/extraction.py`, doubtful fields raise C13), the comparison of a hybrid's visible PDF with its XML (differences raise C09), and plain-language explanations of validation rules.
- **Tools:** `poe llm-smoke` makes one call per feature and records the answers as replay fixtures (`tests/fixtures/recorded/`); `poe precompute-samples` stores the S08 extraction and S10 comparison in `samples/precomputed/`, so new sandboxes show real answers without a call. Both ask for a typed `yes` before spending (`--yes` answers it).
- **The model:** `gpt-5-nano` with reasoning effort `minimal`, the cheapest model the key can use, confirmed by the owner; prices are settings, not code.

## Key decisions

1. **The budget check, the call and the ledger row happen under one Postgres advisory lock.** Two workers can't both pass the same last check and overspend together. The ledger row is committed before an error is raised, so a failed or cut-off answer still counts.
2. **Untrusted text is data, never instructions.** Invoice text goes inside a fence whose closing tag is broken up if it appears in the text, the instructions say the fence holds data, and the answer must fit a strict schema. The injection test puts instructions into the document's text and supposes the model obeyed and returned an IBAN printed nowhere: the value is graded `low`, C13 fires and the invoice goes to review, never straight through.
3. **Tests never call OpenAI.** A fake SDK replays the recorded answers, so the client, the grading and the activities are tested against real model output for free. The cache key covers model, prompt version, both messages and the schema, so a changed prompt can't reuse an old answer.
